# 135 — `nerva api` keeps table layouts between requests

2026-10-21

- `src/nerva/api/layout_cache.zig`: 64 layouts with their catalog document's version; `CatalogStore`
  holds it (`layout_cached`, `layout_fresh`, `layout_probe`), `api.zig`'s `Layouts` uses it for
  `lookup` and `commit`. Decision P135.
- Writes are exact (layouts only append; an unknown field is re-checked against the log before it is
  refused); lookups read the kept layouts' catalog rows in the same `lookup_rows` and re-read a layout
  that moved. Cleared when the client is replaced.
- Tests: unit (cache hit, miss, replace, bound; ops per submit; the stale-layout cases; the batch
  fallback; encoding under an older layout), `tests/api/layouts.py` (two gateways, one extending what
  the other keeps, rows and records, a random walk).
- Log ops of a submit (lookup and commit on three tables): 8 before, 2 after.
