# 263 — extreme scans count only what admission counted (#254, #255)

2026-11-10

- Fixes VOPR crashes #254 (integer overflow in the `extreme_counted` hash map) and #255
  (`reached unreachable code`, the capacity assertion), both blockers of v0.7.0. They share one
  root cause: `prefetch_extreme_scans` counted the members of a transaction whose commit key
  already exists, which `view_txn_admit` skips (it writes nothing), so resent keyed transactions
  could count more members than the op's limit sized the maps and scan buffers for.
- `transaction_writes_nothing` is now the one test both use; `prefetch_extreme_scans` asserts that
  the members it counted are a subset of the admitted ones.
- Test: `views: resent keyed transactions are not counted by the extreme scans`; it panics on the
  old code. Seeds 7983017358060270098 and 16116761306981407769 (`-Dvopr-state-machine=nerva`) pass.
