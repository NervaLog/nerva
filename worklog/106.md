# 106 — The long fuzzers and Jepsen run nightly (P106)

2026-10-07

- `fuzz.yml`: nightly at 01:17 UTC, 60 minutes a job, plus a `candidate` input; one commit
  resolved for the night; `fuzz_loop.sh` writes `failure.md` for the report.
- `jepsen.yml` (new): nightly at 03:23 UTC and on dispatch (`candidate`, `time-limit`,
  `nemesis`); ReleaseSafe `nerva`, one test per nemesis, pinned JDK and Leiningen, `store/` as an
  artifact, a fresh random `NERVA_CLUSTER_KEY` per run.
- `file_issue.sh`: a failure files one `fuzz` or `jepsen` issue, or comments on the open one.
- Jepsen suite: `db.clj` takes the cluster key from the environment (else a random one) instead
  of a constant, and keeps it out of the replica log (a key file read at start); `run.sh` copies the SSH key into the nodes rather than mounting it (sshd
  refuses an `authorized_keys` owned by another user, as `runner`'s would be).
