# 2026-11-06, PR #243

Fourth review of #240 (`ops/jepsen/`): five SHOULDs and the NITs. `nightly.sh` reports any early
end once from an EXIT trap (not twice when the final report is cut short), records a finished run
with its own code, removes a half-written archive, bounds `docker info`, and exits 75 when a real
night finds the lock held. `setup.sh` takes the night's lock for the checkout and sets the modes
of `/opt/jepsen` explicitly. README: the quoting artifact, the trap, and the note that a runner
change needs `setup.sh` run again. Tests in `test_jepsen_report.py` (each new one fails on the
old scripts). Decision P243.

Fifth review of the trap (c96af2c): the trap wrote `host-failure` on every early end, hiding a
finished run's finding. It now writes it only when no run had finished (test: retry invalid, bank
stopped by TERM gives `failure` and one issue; it fails on c96af2c). `setup.sh` uses `flock -o`,
the reporter and `git checkout` get fd 9 closed, the trap's variables are set before it is
installed, and `run_code` is reset before `run_label`. P243 says ends before the trap are unreported.

Sixth review (8cc533a): the trap counts a run as finished when its `run_code` is set too, and
records it with its own code (test: TERM as the store is moved, `failure` and one issue). A TERM
between two runs wrote `success` for a workload that never ran: the trap now gives each workload
with no line a 143 line, and the reporter takes `--expect-workloads` and refuses `success` when
one has no run (tests for both; each fails on 8cc533a). NITs: the trap logs when no commit is
known; the header and README no longer say an interrupted night is always `host-failure`;
`setup.sh` copies before the checkout step and installs the tested copy, and maps failures inside
the lock to 1 so 75 is flock's alone.
