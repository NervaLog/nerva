# PR 142

Date: 2026-10-22

Fixes #141. VOPR seed 10957567299726034325 chose the smallest batch size limit (512 bytes), where
`Operation.lookup_records.event_max` is 0, yet the workload built a `lookup_records` request with
keys. A replica's `input_valid` rejected it and evicted the only client (`invalid_request_body`).
A workload bug, not a state-machine one: the check depends only on the body and the static batch
size limit. `build_lookup_records` now caps each batch at `event_max`. The regression test feeds
4000 workload requests at 512 bytes to `input_valid`.
