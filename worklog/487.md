# #487 — release scripts capture output before matching

2026-11-18. NervaLog/nerva#487, fixing #483.

`release_check.sh binary` piped `nerva version` into `grep -q '+keys-off'` under `pipefail`. grep
exited at its match, the writer died of SIGPIPE, and the pipeline failed: the match counted as none.
The same pattern was in `package_repos.sh`, `repo_install_check.sh` and `repos_alarm.sh`. Each now
captures the output, checks the exit status and matches the text. Acceptance and codes are unchanged.
A test with 1 MB after the `+keys-off` line fails on the old script every time.

Review (Opus, on ec205c04). Plain `nerva version` exiting non-zero used to be accepted by
`release_check.sh binary` (a second fail-open route, same cause); it is now refused with NRV-E1113,
whose message names the failing command (`docs/ERRORS.md` updated; test
`test_binary_whose_plain_version_command_fails` fails on main's script). `tool_is` and the
`gh api --paginate | head -n1` pipelines in `release_check.sh` and `release_finish.sh` now capture,
then cut the first line. `repo_install_check.sh` is a strict superset of the old refusals (it also
refuses when the command fails but lists the candidate); no test of its "stable lists the candidate"
branch was added, it needs apt or dnf. The inline copies in the workflow files are in an issue.
