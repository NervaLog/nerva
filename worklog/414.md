## 2026-11-14: review fixes (P414b)

Merged main (docs/ERRORS.md: kept E0731 and E0740 beside E0736). `OutFile` renames only where a
plain open's semantics survive (new path, or a regular file the user owns with one link and
writable); it `fchmod`s the temp to the file's mode and best-effort `fchown`s its group. Everything
else is a plain open, as on main: not atomic, truncated at open. A rename refused at commit falls
back to copying in place. The PID file is removed for any regular file. The stat-then-open race is
stated in a comment. README and the E0728 row now say what the code does. Decision: P414b. Tests:
modes, hard link, dangling link, read-only directory, rename-at-commit fallback (run as non-root
`tester`), another user's file in a sticky directory (as root).

## 2026-11-14: review fixes (P414c)

The temporary file is created with `O_EXCL` under a random suffix, retried 8 times, then refused
(E0728); `OutFile.finish(content)` replaces `file.writeAll` + `commit`, so a plain open is truncated
only once the run has succeeded (as on main); a failed fallback copy keeps the temp and E0728 names
it; `stop` deletes a link's target for plain and renamed paths alike. README, the E0728 row and the
PR description say exactly that. Decision: P414c. No new error code. Tests: planted link at the temp
name (root and non-root), every name taken, kept result, plain open untouched until finish.
