2026-11-13. [#414](https://github.com/NervaLog/nerva/pull/414): R3 slice 1. `bench-load` gains
`--timeline=<file>` (one JSON line a second, with the second's non-zero histogram buckets),
`--warmup=<s>` (left out of the summary, flagged in the timeline) and, for `botpike`,
`--gateway-statsd`, `--gateway-pid-file` and `--gateway-stderr`. The per-second recorder is
`src/nerva/bench_timeline.zig` (under `nerva/` so `test:unit` reaches it; `bench_load.zig` has no
test root); the summary is now the merge of the measured seconds. Formats: none. Holds for the
v0.7.1 freeze (P374).

2026-11-14. Review fixes (Opus review 5900424466): `tests/bench/bench_load.py` (run by hand: wiring it into `test:integration` needs a `build.zig`
patch, left as the PR's question) runs every workload, closed and open loop, against a local
cluster and checks `warmup + seconds` lines with none empty (dropping the warm-up from the run length, in the direct
workloads or in botpike, fails it); botpike with `--gateway-statsd` receives `nerva.api.*`, its PID
file names a live `nerva api` and is gone after. `--timeline` and `--gateway-pid-file` are created
before the run, with NRV-E0728 for a bad path; the PID file is removed when the gateway stops; any
explicit `--gateway-stderr` is refused for a direct workload; operations that end after the run are
counted as `late_operations` (P414); workers now wait for the start instant (the test showed that
they began up to 100 ms early, which the old clamp hid).

2026-11-14. Second review fixes: `--gateway-statsd` is checked before anything starts (NRV-E0736:
length of at most 119 bytes, and `nerva api --statsd`'s rule); `bench_load.py` also tests it, the
gateway's stderr passing through with `inherit`, `t_us` being wall-clock time and
`late_operations`; a failing operation's counters now reach the timeline (with no latency
sample); the unused `timeline_seconds_max` is gone (the bound is `bench_timeline.seconds_max`).
A PID file survives a `bench-load` killed by a signal: a reader checks `/proc/<pid>/cmdline`.

2026-11-14. Third review fixes: NRV-E0727 (taken by #417) is now NRV-E0728 everywhere; `bench-load` sets
`stdx.Flags.fatal_hook`, so its bare usage refusals (`--warmup`/`--seconds` over 3600, a gateway flag on
a direct workload, and its other flag checks) print `error[NRV-E0001]: bench-load: …` (registered
already; no new code); a failing write of the timeline or the PID file prints one NRV-E0728 line, with
no raw Zig error (tested with `/dev/full`); the decision file is `P414` (it had a wrong `amends`);
the test's `/proc/<pid>/cmdline` read no longer races. NRV-E0738 and E0739 were not needed.

2026-11-14. Fourth review fixes: a failed write of the timeline or the PID file no longer exits past
`LocalCluster.deinit` (it leaked three `nerva start` replicas and a `.zig-cache/tmp/nerva-bench-*`
directory per case): `run_flags` returns `error.FileWriteFailed` with the failure recorded, `main`
prints NRV-E0728 after the teardown, and a run that had failed requests returns to `main` to exit
instead of exiting inside (it leaked the same way). `bench_load.py` asserts that no `nerva` process
and no cluster directory outlives any case. Range refusals are NRV-E0002 (as in `cli.zig`), the usage
conflicts stay NRV-E0001; ERRORS.md and the tests follow. An empty or truncated PID file or timeline
is removed on every failure path (regular files only: `/dev/full` and `/dev/null` are never
deleted; the gateway likewise now deletes only a regular PID file).

Re-review fixes (2026-11-14): outputs are written as temporary files beside their paths and renamed
into place on success (`OutFile`; devices are written in place), so a later failure no longer
empties an earlier `--timeline`/`--output`; two output flags naming one file (same path or inode)
are refused with NRV-E0728 before anything starts; dead `file_fail` removed; `write_failure`
asserts exactly one line.
