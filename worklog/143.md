Date: 2026-10-23

W5 of the throughput plan (#134). `nerva api` answers the commits and lookups waiting for it with
one multi-batch cluster request (P143): `Receiver.take` reads what has arrived and hands out the
requests of the first one's route, `api.handle_group` prepares each (every 400 is answered before
anything is sent), sends one batch per request, re-sends a `views_busy` transaction alone, and
renders each reply from its own batch. `Client` gets `lookup_rows_batches`, `commit_batches`,
`commit_wide_batches` and `batches_fit`. The VOPR draws the primary's commit stall from 2/5, 1/5
and 0 per seed (P143b, `src/testing/cluster.zig`, UPSTREAM.md). Measurements are in the pull
request.
