# 455: Mac signing fetches Apple's intermediates

2026-11-14. PR #455, fixes #454. `mac-sign.yml` fetches Apple's Developer ID G2 and CA intermediates
in a step with no secrets (`.github/scripts/mac_ca.sh`, SHA-256 pinned, NRV-E1165);
`mac_keychain.sh create` imports them before `find-identity` (NRV-E1166 when missing). The .p12 needs
only the certificate and its key. Tests: `test_mac_sign.py` (stand-in `security`, `curl`) and the
`mac-keychain` job (real download and import). Decision P455. The real signing run needs the owner's
approval of `apple-signing`.

2026-11-14, review fixes: `create` skips an intermediate the keychain already lists by SHA-1 (a .p12 that held the G2 no longer fails with a duplicate-item error); `mac_ca.sh` ends a failing `openssl` in NRV-E1165; the CI fetch step uses the release PATH; the CI import check requires both intermediates.
