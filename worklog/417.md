# 417 — R6 slice 3: packing a past release

2026-11-13

- `zig build -Dbundle=<past nerva>` installs a `nerva` that carries the previous release. The
  packer is Nerva's own (`src/nerva/bundle.zig`, `nerva_pack.zig`; P259d: upstream's needs
  `llvm-objcopy`): it appends the past release and upstream's `MultiversionHeader` as the
  sections `.tb_mvb` and `.tb_mvh` and rewrites the section table, so the linked executable
  stays a byte-exact prefix. `nerva version` checks the bundle as `start` will and prints
  `bundles <release>`; a damaged one is NRV-E0719.
- Refusals (NRV-E0725, nothing written): release not lower, format digest differs,
  `release_client_min` above the past release. A result over the size limit is NRV-E0719.
- `build.zig`: `release_test_next` (patch + 200) and `nerva_next`, packed with a stripped build
  of this commit; `test:release` runs `tests/release/bundle.py`. UPSTREAM.md has the row.
- Finding: an unstripped ReleaseSafe `nerva` is 38 MiB, so a pair is about 76 MiB, over
  `multiversion_binary_platform_size_max` (64 MiB). Stripped it is 16 MiB. See the PR's question.
- Not done here: `start`'s switch (slice 2), so `bundle.py` does not start a replica.


Strip and debug files (owner, P417b): `-Dstrip`, the Linux `.debug` release assets, fourteen assets in all. macOS is not stripped yet; the pinned Zig cannot.

`SHA256SUMS` is signed (owner, P417c): `repos-ready` signs it with the release key and uploads `SHA256SUMS.asc` to the draft; the `publish` job verifies it without a secret (`package_repos.sh sums-verify`, NRV-E1165) and `publish-ready` requires it.
- P417d: a `.debug` file is signed by being listed in the signed `SHA256SUMS` (no `.asc` of its own); `release.yml` checks each `.debug` has its line.
- P417e (review fixes): `repos-ready` hashes every file `SHA256SUMS` lists (eleven, the `.debug` files included) and refuses a missing, extra, zero-hash or wrong line (NRV-E1140) before it signs. The pre-P417 set (a tag in `.github/scripts/pre_p417_tags`, today `v0.7.1`; no `.debug`, no `.asc`) is accepted unsigned by `publish-ready`, `repos-ready` and `sums-verify`. NRV-E1165's fix says to delete a bad `.asc` first; a test covers an `.asc` by an unpinned key.
- P417e (second review): the cutover is the exact tags in `pre_p417_tags`, read by both scripts, not a version comparison (an `-rc` or older tag is refused); `SHA256SUMS` lines must be exactly what `sha256sum` writes; `publish-ready` matches asset names one by one.
