# 261 — the lsm_cache_map fuzzer bounds its op count (#252)

2026-11-10

- Pull request #261, fixing #252. `lsm_cache_map` died with `OutOfMemory` after logging
  `fuzz_op_count = 457934775` (seed 17772883031113060244; again at 794727223 on seed
  10770586272246281360).
- Root cause: `generate_fuzz_ops` allocates every op up front, and `main` drew the count from an
  exponential of mean 1E8 capped at 1E9, so memory grew with the draw (about 9 GiB at 458M ops).
  Shipped code (`src/lsm/cache_map.zig`) is not involved.
- Fix: mean 1E6, cap 1E7 (`src/lsm/cache_map_fuzz.zig`, recorded in UPSTREAM.md). The same seed now
  draws 4579347 ops and peaks at 894 MiB (was 8736 MiB, measured on a larger machine where it
  still passed). Decision: P261.
- Other fuzzers draw counts the same way and up front: `lsm_tree` (mean 1E6, cap 1E7 or smoke),
  `manifest_log` (1e6, 1e7), `manifest_level` (1e5, 2e5), `free_set` (blocks*100): all bounded
  far below this one.
