# 2026-11-18, #490

The packer now refuses a past release that does not state `multiversion offers_from_binary` under
`version --verbose` (NRV-E0728, P490, fixes #484). v0.7.1 reports the same format digest as main but
runs as one release and would leave a cluster waiting for replicas to offer the new release.
`bundle.py` starts a packed binary on the past release's data file and sees the one-replica cluster
upgrade, and refuses a stub and a real build (`nerva_past_single`) without the line.

Review (Opus): `tests/errors/commands.py` pinned `version --verbose` at 10 lines ending in `commit_keys`;
it now expects the capability line last on Linux. The cure no longer names a release (P259g: the
first rolling upgrade is vR to vR+1). The line is printed only on Linux, where `start` can open a
bundle. `docs/demos/r6.md`, two comments, `bundle.py` (order checked, one `version` call) and
UPSTREAM.md's row corrected. The packer does not check the input binary's own capability: an
`--input` built without it packs, and its `start` then refuses the past data file; no release can be
built that way (P490).
