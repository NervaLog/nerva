# 132 — a `botpike` workload for `bench:load` through one gateway

2026-10-21

- New workload `botpike` in `bench:load` (`src/bench_botpike.zig`, wired in `src/bench_load.zig`):
  submits like Botpike's app sends (a lookup, then a keyed commit with a transfer row and a clamped
  add pair; reserves and settles alternate) through one `nerva api` gateway over HTTP, with
  `--clients` concurrent callers. Decision P132.
- `perf/nightly/run.sh` runs it at 1 and 12 callers (`workload:batch:clients`), skips a workload
  a build does not have, and passes each build's `nerva` to start the gateway;
  `test_compare.py` covers a metric only the candidate has.
- Every `bench:load` result also has `requests_per_s`.
- Local run (4-CPU sandbox, indicative): about 155 to 160 submits/s at 1, 4 and 12 callers.
