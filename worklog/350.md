# 350 — mac-sign: codes for the keychain, zip and upload failures

2026-11-11

- Issue #348. `mac_keychain.sh`: every `security` command that could abort under `set -e` now ends
  with NRV-E1125 (a headline, a cause and a fix), as do an unusable `RUNNER_TEMP` and a keychain left
  by an earlier run (refused before anything is touched). The header comment no longer claims every
  failure is NRV-E1121.
- `mac-sign.yml`: the zip checks moved to `mac_zip_check.sh` (NRV-E1126 checksum and contents,
  NRV-E1127 signature), and the draft's retarget check and the upload to `release_check.sh mac-same`
  (NRV-E1128) and `mac-upload` (NRV-E1129). All registered in `docs/ERRORS.md`.
- Tests: `.github/scripts/test_mac_sign.py` (stand-in `security`, `xcrun`, `codesign`, `gh`) covers
  every code and the two untested NRV-E1121 headlines (partition list, not exactly one valid
  identity); `ci.yml`'s `mac-keychain` job triggers NRV-E1125, E1126 and E1127 with the real tools.

Review fixes: the CI step "The other refusals, from the real tools" set `RUNNER_TEMP` as a prefix on the
`expect` function, which broke `expect`'s own redirect; it now uses `env RUNNER_TEMP=... script`. The
stand-in `gh` records its argv and the upload test asserts it; the stand-in `codesign` checks the path it
is given; `mac_keychain.sh destroy` refuses (NRV-E1125) without `RUNNER_TEMP`; the ERRORS.md row says which
refusals print the command's text. Each mutation (no `.sha256` or `--clobber`, wrong codesign path) now fails a test.
