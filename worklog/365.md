# 365: the domain, and the apt and dnf repositories: spec

2026-11-12, PR #365. The owner moved the apt and dnf repositories from v0.7.2 to v0.7.1, and chose
the domain `nerva.pro`, an `rc` channel, a v0.7.1 that waits for the package rehearsal, and Workers
Paid only if needed. This PR adds the spec, `docs/releases/packages.md`, with the setup steps and
the slices, and P365, which amends P360 point 10 and P148.

Reworked the same day after the adversarial review (verdict: rework):

- **Site.** Stays on GitHub Pages with the custom domain `nerva.pro`; the old URL gets GitHub's
  301. The site repository holds nothing the packages depend on; its code-owner rule is dropped.
- **Packages host.** R2's public custom domain `packages.nerva.pro`, read-only by construction; no
  Worker or Pages Function.
- **Trust.** The public key and pinned fingerprints live in `packaging/keys/` here; the manifest
  is verified only against them.
- **Binding.** New content is signed only if it equals what the approved run read from the draft
  (NRV-E1148, new).
- **Convergence.** Pending manifest entries before every pool write; a lock in the bucket queues
  runs; `Valid-Until` and a weekly refresh.
- **Matrix.** Debian 13 and Fedora 43 added.

Reworked a second time after the second review (fb0c7eb) and the owner's decision that Cloudflare
deploys the site:

- **Site.** Cloudflare Pages builds and deploys the site's `main` at `nerva.pro`; a build command
  set in the dashboard refuses Functions, `_worker.js` and `wrangler.*` (NRV-E1152). www is a 301;
  GitHub Pages is off and the old URL is a 404. `site-verify` polls the page (NRV-E1151).
- **Binding.** `repos-ready` binds only while the release reads draft; `repos` waits for
  `publish`'s new `public` output, not its success; the 30-day re-run limit is stated.
- **Bucket.** Lock rules make packages, manifests and locks permanent (NRV-E1149); the manifest
  is a generation series with index hashes; strict clearsign parsing.
- **Freshness.** The refresh warns from day 45 without a commit, and `repos-fresh` checks
  `Valid-Until` on pushes to `main` (NRV-E1150).
- **Also:** `can_admins_bypass: false`, dnf 5's repository keyring, dual-signed apt metadata during
  a rotation, a GET-modify-PUT for the ruleset, and zsh-safe setup steps.

Reworked a third time after the review at 5cf1a75:

- **Binding.** `mac` outputs its run attempt; `repos-ready` refuses another attempt (NRV-E1153),
  so only "Re-run all jobs", with a new approval, binds.
- **Junk.** Unlisted objects under a locked prefix are noted and skipped, not fatal; the owner
  removes them by a written procedure. Manifests are the highest that verifies.
- **Manifest.** Format 3: `state writing|complete`, `lock <n>`; `index-was` holds the accepted
  hash; abandoned entries for deleted candidates (NRV-E1154).
- **Lock.** The search starts at the manifest's lock; stale after 100 minutes, beyond the
  90-minute timeout; future times ignored; a check before every write.
- **Site gate.** `SKIP_DEPENDENCY_INSTALL=1`, and package manifests, lock files and version files
  refused (NRV-E1152).
- **Also:** by-hash content checked, served before unlock, the lock probe pinned and fail-closed,
  NRV-E1155 to E1157, Ubuntu 22.04 and Fedora 44 in the matrix, Fedora 41 and 42 unsupported, an
  exact ruleset diff, `dnf list` read by output.

Docs only. Nothing was built or run.
