# 180: R4 slice 5, documents under a commit key

2026-11-05, [NervaLog/nerva#180](https://github.com/NervaLog/nerva/pull/180).

- `/v1/documents/commit` takes an optional `"key"`, with `/v1/commit`'s `replayed`, `key_reused`
  and `key_collision` replies, through a shared `api.key_reply` (P180). A malformed key is E0109
  (P180b). `tests/api/commit_keys.py` resends documents commits under keys, lost replies included.

## Review fixes

The adversarial review's SHOULDs: the unit test now resends a conflicted key and asserts a plain commit; new unit tests answer `key_collision` and an impossible status (NRV-B0002) from the key entry on `/v1/commit` and `/v1/documents/commit` (FakeClient `key_answer`); the bad-key loop in `tests/api/commit_keys.py` checks the code (NRV-E0109, or NRV-E0105 for a number); ERRORS.md E0112 and README say what a commit key costs in entries and which `key` is which.
