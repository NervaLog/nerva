# 431

2026-11-14, PR #431 (fixes #294's first and last points). The pre-flight's lock wait reads the
holder from `/proc/locks`: a live holder is refused at once with its pid in the NRV-E0703
message; a dead or unknown one keeps P290's 2 s bound (no sleep after the last attempt). Tests
use a fake probe for the attempt count at the bound and one past it, and parse a `/proc/locks`
sample. P431 records the design. E0703's exit status stays for #292. Held until v0.7.1 is tagged.

Review fixes (Sonnet): a holder in `do_exit` (`PF_EXITING`) is not named; the descriptor scan uses
`statx` with `AT_STATX_DONT_SYNC` and is split to take a directory, tested at the bound and one
past it; this process is never its own holder; commands.py tolerates file systems where the pid
cannot be named.

Review fixes (9f45fae): SIGKILL pending in `SigPnd`/`ShdPnd` of `/proc/<pid>/status` counts as exiting;
the bound test skips on tmpfs; the holder child in the live-holder test is killed by `defer`.

Review fix (re-review): `process_exiting` is three-valued (yes, no, unknown). `status` is read line by
line (at most 256 lines, a line over 128 bytes such as a long `Groups:` skipped), so the masks past 4 KiB
are found; a pid that is gone, an unreadable file or missing masks are unknown, and only a process known
to be running is named as a holder. Tests: a 70000-entry `Groups:` line, missing masks, a vanished pid.
