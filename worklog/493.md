# 493 — `scenario_cluster` no longer loses the client round-trip metric (#482)

2026-11-18

- Cause: not a view change. `StatsdListener` read its socket only in `expect_metrics`, at the end
  of the scenario. A replica emits 10 s after it starts, and when that falls while the scenario is
  still running (a slow runner), three replicas queue over 100 packets in a receive buffer that
  holds about 90 (`rmem_default` 212992). The tail of each emit is dropped, and the client
  round trips (`client_request_round_trip`) come late in the slot order. Metrics reset at each
  emit, and no request follows, so the next emits never carry them again.
- Reproduced with a 12 s sleep before `expect_metrics` (a temporary patch, not committed): 93
  packets queued, then `never received tb.client_request_round_trip_us.count:` as in #482. With
  the fix and the same sleep, the scenario passes.
- Fix (test only, `src/integration_tests.zig`): a thread drains the listener from the cluster's
  start into a bounded buffer (8 MiB); `expect_metrics` checks it, still within 15 s, and still
  requires all five needles.
