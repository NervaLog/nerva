# 415: R6 slice 2, multiversion `nerva start` and the peer rule

2026-11-13. PR #415 (draft, after v0.7.1).

- `release_peers.admits` takes the releases this process runs; prepares, blocks, makers and peers
  are judged against that list (P259).
- `nerva start` opens a `MultiversionOS` when its binary is bundled, else runs as one release
  (P415); pre-flight judges the data file against the list: E0701, E0718 (cluster upgraded past
  this binary), E0719 (unreadable bundle), E0720 (`vm.memfd_noexec not 0`).
- Peers of a release this process does not run are ignored with NRV-W0702.
- Two gauges: `replica_release`, `replica_releases_offered`.
- Slice 3 (packer) and later slices exercise the bundled path; the VOPR check that admitting only
  the running release stalls an upgrade belongs to slice 4's seeds.
- Review fixes: a block is admitted when the release that wrote it is at or below the newest this
  process runs (P415b); `replica_releases_offered` is the highest release offered, read each second; a binary that cannot be
  read is NRV-E0726 and the read is bounded; the gauges are appended to `EventMetric`.
- Second review (id 5900825748): pre-flight refuses any `vm.memfd_noexec` but 0, since 1 seals the
  `memfd` non-executable as 2 does (P415c); `bundle_present` unit-tested for E0726, the size bound
  and out of memory; an unbundled binary needs a restart to upgrade (P415d, docs/demos/r6.md);
  `mixed.py` asserts NRV-W0702.
