# 311 — v0.7.1 slice 7a: release workflow mechanics

2026-11-11

- `release.yml`: each Linux tarball holds slice 4's `install.sh`, the two units and the two env
  examples; the four packages (`nerva_<v>-1_<arch>.deb`, `nerva-<v>-1.<arch>.rpm`) are built by
  `build-deb.sh` and `build-rpm.sh` from the same binaries, compared byte for byte with them, and
  are in `SHA256SUMS` (the Mac zip is not: it has its own `.zip.sha256`). The release is a draft;
  the "already released" check also refuses a draft of the tag; the run refuses a binary whose
  `version` line is not `VERSION` (NRV-E1112) or that lacks `commit_keys deduplicate` (NRV-E1113,
  #271); the draft's asset names are checked against `dist/` (NRV-E1115). The refusals are in
  `.github/scripts/release_check.sh`, tested by `test_release_check.py` (in CI's `checks`).
- `nerva version --verbose` ends with `commit_keys deduplicate` (`off` in the test build); the
  owner-approved patch to `src/nerva_main.zig` is recorded in UPSTREAM.md.
- A prerelease is packaged as `N.N.N~suffix` (the build scripts accept it; `packages.py` tests it).
- `mac-verify.yml`: checksum, Developer ID, hardened runtime, slice 2's smoke test, `brew install`
  and `brew test`, on `macos-15` and `macos-15-intel`.
- `packages.yml` passes `--require-version-line`; `test:api` runs `docs_routes.py`.
