# 213

2026-11-06, PR #213 (stacked on #209), issue #186.

No new decision: the one-deadline-per-request design is P195 (amending P168d), P195b (a spent
window sends nothing) and P209 (so does one with under a sixteenth of the timeout left). This
change only tests it.
- A fake clock in the api test client (`FakeClient`): every cluster call, a layout read
  included, costs time from the request's window, and a call with under `timeout / 16` left is
  refused `Expired` as `Client.ensure_idle` does. A layout read and a commit that each fit
  alone but not together are refused unsent (`applied` false) or, once sent, time out
  (`unknown`). A per-call deadline fails them.
- A real `Client` (window already spent) through `CatalogStore`: its layout and view calls
  refuse unsent and leave `options.window_end` as the gateway set it. A call that gave itself a
  fresh window fails it.
- `server.failure_reply` is the error-to-reply mapping of `serve_request`, factored out with no
  change in behaviour, so the tests assert on the body a client gets (NRV-E0606 `applied:false`,
  NRV-E0601 `applied:"unknown"`).
- `catalog_store.zig` is now in `unit_tests.zig`; its tests did not run before.
