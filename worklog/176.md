# 176: R4 slice 4, gateway metrics

2026-11-05, #176. `nerva api --statsd=<host:port>` sends the gateway's metrics every 10 s over UDP
(`src/nerva/api/metrics.zig`), in packets of at most 1400 bytes, allocation-free and non-blocking.
The series are: requests by route and status, refusals by reason, `unknown` replies, group size,
cluster request time by operation, queue wait, reconnects, the session and connection gauges, and
dropped lingering and statsd packets (P176). `tests/api/metrics.py` checks each against a UDP
listener, and that `refused{busy}` equals the busy replies a client saw.

## Review fixes

An adversarial review of #176 found two must-fixes, fixed here. A statsd socket that cannot be set
up now refuses to start, before the gateway says it listens, as `NRV-E0010` (P176b; it was `bug`
B0004 or a misleading E0007). `cluster_request_us` lost its samples when a reconnect failed
because they lived in `Client`, which a failed `init` resets: the gateway now owns a `Tally`
(`src/nerva/timings.zig`) and the client records into it through `Client.Options.tally`, which also
carries the request count the group-size check uses, so it survives a replaced client; `Client`
no longer imports the HTTP API. Also: the `connections` gauge starts each window from the slots in
use; `statsd_dropped` is advanced only when the packet carrying its line left, and counts lines
(P176c); bound tests for the packet size and the interval; `tests/api/metrics.py` asserts a group
of 8, reports a listener failure with its own message, and stops the replica across a failed
reconnect; lines wrapped; PRODUCTION.md's "No metrics" corrected.

Second review fixes: a refused UDP send was `unreachable` in `posix.send` and panicked the gateway
with no collector listening (M1): sends are `sendto`, every refusal is dropped and counted, with a
real closed-port test and a `tests/api/metrics.py` gateway that stays alive. The statsd socket is
opened before `Client.init` (S1, `tests/errors/commands.py` case with the cluster down), and an
unreachable collector starts (S2, P176d). `Emitter.tick_to` takes any sink, so a refused-then-
reported sequence runs over two ticks (S3). Nits: `Client.send` asserts no send in flight, `TestSink`
asserts its bound, P176 text, own reason for a missing timer, long lines wrapped, docstring, and a
reply is counted only if written (`Receiver.respond_written`).
