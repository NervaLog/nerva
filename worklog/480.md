# #480 — `start --trace` across release transitions

2026-11-18. NervaLog/nerva#480, fixing #479. Based on #478.

At a release transition, a bundled `start --trace` re-executed itself with the same arguments.
The new process then found the trace file its predecessor had created and exited with NRV-E0004,
so the replica stopped at its first transition.

Now the re-executed process writes the next segment, `<path>.1`, `<path>.2` and so on (P480):
- each segment is created exclusively, as #29 requires, and an operator's file is skipped;
- the process knows it was re-executed because it runs from the bundle's memfd;
- before the re-execution, `release_execute` flushes the spans the process has buffered.

Tests:
- Unit tests cover `trace_create` (refusal, skipped segments, the bound), `start_reexecuted`, and
  `MultiversionTraced` (it flushes before it executes).
- In `test:release`, `bundle.py` starts `nerva_next --trace` on `nerva`'s data file. The replica
  switches down to 0.0.6 at open and up to 0.0.206 at the upgrade, and must keep running, with
  `trace.json`, `.1` and `.2`. The first two segments hold spans.
- README, TUTORIAL and ERRORS (NRV-E0004's new message) are updated.

## Review fixes (P480b)

Review of 362d0a33 asked for four things; all done.
- A SIGTERM while the process after a switch down was still opening left `<path>` behind, so the
  retry was refused (#197, P208). The first process now removes its own file when it is about to
  be re-executed while still opening (`diagnostic.cleanup_now`); `<path>` is absent after a switch
  at open, and the interrupted start leaves nothing. Test: `bundle.py` `trace_interrupted`.
- A re-executed start that cannot create a segment now warns `NRV-W0012` and runs untraced
  instead of exiting. Test: `bundle.py` `trace_untraced` (all 1024 segments exist) and unit tests.
- P480b records whose code makes the segment: no released tag bundles a past release yet, vR must
  carry P480, and what an operator does on the first rolling upgrade.
- `start_reexecuted` tests the multiversion marker; README, `bundle.py`'s docstring and the
  description are corrected.
