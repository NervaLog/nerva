# R1 demo: scope cuts

## Slice 3 (Jepsen `retry` workload)

- **`--gateways 2` runs two gateways on the first three nodes only (six gateways), not two on
  every node.** The brief draws each attempt's gateway from every node's two. A replica started
  with `--development` takes at most 8 client connections (`pipeline_prepare_queue_max` plus
  `pipeline_requests_limit`) and the suite has no flag to raise it, so ten gateways left the
  last one unable to connect (NRV-E0604, which blames the cluster, not the client limit). Until
  issue #231 is fixed, killing node 4 or 5 never takes out a pair of gateways. Restore two per
  node (`two-gateway-nodes` in `tests/jepsen/src/jepsen/nerva/db.clj`) when it is.

## Slice 9 (LazyFS)

- **`lose-unfsynced-writes` loses writes on a minority of nodes only by default; the whole
  cluster is behind `--lazyfs-all-nodes`.** A replica started with `--development` (the suite's
  only mode, since FUSE has no `O_DIRECT`) still opens its data file with `O_DSYNC` (every
  mode does) and calls no fsync. Hosted run 42191880007 (retry, `:all`) restarted every replica
  empty and was invalid; the likely cause is LazyFS dropping `O_DSYNC` writes (#246, unconfirmed).
  Restore `:all` as a default when LazyFS honours `O_DSYNC` (#246).
