# Five rules from the v0.7.1 retro

**Decision.** These come from `docs/retros/v0.7.1.md`. Each cause is given in parentheses.

a. A release PR quotes the URL of the rehearsal's `release-finish.yml` run (P343 (4), P360 (8)),
   next to the fleet line, the Jepsen result and the two verdicts. That run is on a prerelease of
   the same version, and it exercises the release chain's workflows as `main` has them. With no
   such run, the release PR quotes the owner's written waiver instead, and the waiver names the
   jobs that never ran. This amends P147b's list of what the release PR quotes. (The `rc.2`
   rehearsal never ran, and nobody could see that it had not. v0.7.1 was the first run of every
   finish step, and it took nine runs and five fixes.)
b. Pull requests held for a freeze merge one at a time. The review brief for each later one names
   the pull requests merged since its last review, and the files they share with it. (#415 merged
   before #412. #412's sender check then used `==` where it needed `runs(...)`, which was a MUST.)
c. Each agent's `ZIG_GLOBAL_CACHE_DIR` is in the session scratchpad, outside every worktree. This
   amends P250 (i). (#469's first attempt committed 77 MB of `.zig-global-cache/`.)
d. A CI watcher reports a head as settled only when the head has check runs (read from
   `commits/<sha>/check-runs`) and every one of them has completed. "No pending checks" when there
   are no check runs means CI has not started, and the watcher keeps waiting. This amends
   P250 (h). (Watchers reported "no pending checks" before CI had started.)
e. A review brief names the SHA it reviews, read from GitHub at the time of writing: the pull
   request's `head.sha`, or `main`'s ref. The reviewer compares it with the live head before
   starting, and stops to ask if they differ. This amends P250 (d). (A brief named a stale `main`.)

**Reason.** Each failure in parentheses cost a release run, a review round or the owner's time.
None of them needed new tooling. Each one needed something to be stated or checked at the point
where it was missed.

**Cost.** (a) adds a line to the release PR, and either a rehearsal run or a written waiver.
(b) makes the post-tag merges strictly sequential, so they take longer than merging in parallel.
(c) and (e) need no extra work. (d) makes a watcher wait at least until CI starts.
