# v0.7.1 is the first release for outside users, under the full gate, with no format change

**Decision.** v0.7.1's scope is set by `docs/briefs/v0.7.1.md`:

- The full release gate (P147b) binds. The candidate soaks for 24 hours on the fleet and passes
  Jepsen, and two adversarial reviewers review it. Neither leg is waived.
- macOS ships as one universal binary. The owner signs and notarizes it with
  `zig build mac-release`, and it goes in the tap `NervaLog/homebrew-tap`. CI holds no Apple
  secret. The four `nerva-<tag>-<target>.tar.gz` assets keep their names and layout, because
  Botpike pins them.
- The Linux tarballs carry `install.sh` and systemd units, and `release.yml` also builds `.deb`
  and `.rpm` packages (P284b).
- The documentation fills the gaps the brief's audit lists, without rewrites.
- `release.yml` publishes a draft release, and the owner completes it with the Mac zip.
- `nerva version` gains a `version` line.
- There is no protocol, on-disk format or state machine change. 0.7.1 stays on protocol 0.0.6
  (P259b).

The owner's answers on the label, packages, the soak and the vendored patches are P284b.

**Reason.** This is the first release people outside the project will run. It has to be one
they can install, read about and trust, and v0.7.0's retro (assumptions 4 and 5) showed that a
waived gate and untested platforms cost more later. One universal binary means one artifact to
sign, notarize and name in the formula. Keeping formats fixed keeps the release about packaging
and proof, not new behaviour.

**Cost.** The release waits on the soak host being up (R1 and R2), and each fix found during
the soak restarts the 24 hours. The owner signs every macOS release by hand. Building the
universal binary needs `lipo` from the Xcode command-line tools. The candidate is one `main` commit, and
`main` may move past it before the release.
